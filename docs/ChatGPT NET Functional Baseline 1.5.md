# 1. 产品定位修订

7. ChatGPT NET 的首要用途是在使用 ChatGPT 时及时保存重要内容，降低遗漏信息的风险。
8. 用户负责决定：
   - 摘录哪些内容；
   - 哪些节点存在层级关系；
   - 父子关系的方向；
   - 无关系内容大致放在哪里。
9. 系统负责：
   - 保存用户摘录；
   - 维护正文锚点；
   - 在用户建立或增加节点关系后，把受影响层级自动排成清晰、稳定的图形；
   - 生成短、清楚、无冲突的关系线。
10. “自动排列”只处理几何位置和线路，不根据文字内容自动判断、创建、删除或改变层级关系。
11. 本产品仍不提供 AI 摘要、AI 分类、AI 自动建图或 AI 自动判断上下游关系。
12. 1.3 第 3～4 条继续有效，但“用户自行决定如何放置节点”解释为：用户直接决定自由/普通移动的落点，并通过建立关系表达层级意图；关系图内部的精确几何位置由自动排列负责。
13. 1.3 第 9 条修改为：不提供 AI 自动整理，但必须提供由用户关系操作触发的确定性自动布局。

# 2. 核心术语

14. **位置意图**：用户把节点或选中节点组释放在画布空白处，表示希望它们位于该位置附近，不改变已有关系。
15. **关系意图**：用户把节点或选中节点组释放在另一个未选节点主体上，表示希望建立父子关系；被拖动节点为子节点，目标节点为父节点。
16. **受影响连通层级**：新增、删除或改变关系后，与该关系任一端通过父子关系相连的全部节点和关系线。
17. **无关内容**：不属于受影响连通层级的自由节点、孤立节点、其他连通层级及其合法线路。
18. **独立子树**：某节点及其下游节点形成一个不再通过任何关系连接到外部节点的完整层级分量。
19. **稳定顺序**：同级节点已经形成的从左到右顺序；没有结构性必要时不得反转或随机改变。
20. 系统只根据用户释放目标区分位置意图和关系意图，不增加永久的“手动节点”“自动节点”或隐藏锁定状态。

# 3. 操作与排列规则总表

21. 以下操作按本表确定最终位置：

| 用户操作 | 操作含义 | 最终位置规则 |
| --- | --- | --- |
| 无关系节点拖到空白处 | 位置意图 | 优先使用手动落点 |
| 已经解除关系的节点拖到空白处 | 位置意图 | 优先使用手动落点 |
| 已有关联的节点拖到空白处 | 位置意图，不改变关系 | 优先使用手动落点，只更新受影响线路 |
| 独立子树的根节点拖到空白处 | 移动完整层级 | 独立子树整体平移，内部排列不变 |
| 单个节点拖到另一个节点上 | 关系意图 | 建立关系后自动排列受影响连通层级 |
| 给已有子节点增加第二个或更多合法父节点 | 关系意图 | 自动排列合并后的受影响连通层级 |
| 多个无父节点拖到共同父节点上 | 批量关系意图 | 原子建立关系并自动排列，保持被选节点稳定顺序 |
| 只执行“解除”或双击关系线解除 | 只改变结构 | 节点暂时保持原位置，不因解除动作自动跳动 |
| 从备忘录拖回画布空白处 | 位置意图 | 优先放在释放点附近，不自动建立关系 |

22. 释放在空白处时，系统不得擅自建立、删除或改变任何父子关系。
23. 释放在目标节点上并通过合法性检查后，精确落点不再是节点最终坐标；系统必须接管受影响层级的排列。
24. 关系意图的落点可以用于推断新节点在同级中的左、中、右相对顺序，但不得迫使系统保留会破坏层级图的精确坐标。
25. 拖动过程中不持续执行完整自动布局；在指针释放并确认操作类型后最多执行一次结构提交所需的布局流程。

# 4. 普通手动移动

26. 普通手动移动优先尊重用户释放位置，多选节点始终保持组内相对位置。
27. 如果释放位置合法，只重新规划与被移动对象直接相关的线路，不移动无关节点。
28. 如果释放位置造成节点重叠、线路穿过节点、非法交叉或其他硬性冲突，处理顺序为：
   1. 只重新规划相关线路；
   2. 把被移动对象调整到距离释放点最近的合法位置；
   3. 仍无合法位置时取消本次移动并恢复操作前状态。
29. 普通手动移动不得为了获得更整齐的图形而自动重排整个连通层级。
30. 如果移动的是独立子树根节点，整棵独立子树作为刚性整体平移，内部节点位置和内部线路结构保持不变；只允许整体避让边界或无关障碍。
31. 如果被移动节点仍通过多父关系与外部层级相连，则它不是独立子树，不能把共享下游或外部层级一起拉走。
32. 用户先解除节点关系、再把已经独立的节点或子树拖到空白处时，按普通手动移动处理，不触发自动层级整理。
33. 取消、Esc、页面失焦或无合法解时，节点、线路和关系全部恢复到本次移动开始前的状态。

---

# 5. 建立关系后的自动排列

34. 单条关系、批量共同父关系或新增多父关系通过语义合法性检查后，必须自动排列受影响连通层级。
35. 自动排列的首要目标依次为：
   1. 节点和线路满足全部硬性无冲突规则；
   2. 父节点在上、子节点在下，方向一眼可辨；
   3. 同层节点横向排列，分支间距清楚；
   4. 线路短、正交、少拐弯，并正确使用允许的共享主干；
   5. 整体图形紧凑但不过度拥挤；
   6. 布局结果稳定、可预测。
36. 自动排列不得把“勉强无冲突但明显绕远、层级颠倒或分支混杂”的结果视为合格。
37. 关系建立时，已有目标层级的根节点或整体视觉中心应尽量作为固定参照；新加入节点或子树优先移动到合法层级位置。
38. 如果只移动新加入内容无法得到合理图形，可以依次扩大调整范围：
   1. 新节点及其子树；
   2. 附近兄弟节点和直接相关分支；
   3. 整个受影响连通层级。
39. 不得仅为了少移动几个节点而接受明显较差的最终图形；在最终图形同等合理时，才优先选择移动节点更少、位移更小的方案。
40. 无关内容在自动排列前后的坐标、相对顺序和合法线路必须保持不变。
41. 如果无关内容形成障碍，自动排列只能在剩余合法空间中安排受影响层级，不得移动障碍为关系图让路。
42. 自动排列必须遵守有限画布边界；不能通过把内容放到不可达位置来假装成功。

---

# 6. 层级图形规则

43. 层级图默认采用从上到下的树状图/组织结构图方向。
44. 每条边从父节点指向子节点，任何子节点的顶部不得高于其直接父节点的底部。
45. 同一父节点的直接子节点应位于下一视觉层并从左到右排列。
46. 父节点应位于其直接子节点组合的视觉中心上方；只有避让边界或无关障碍时允许合理偏移。
47. 具有共同父节点的多条关系应在父节点附近共享一段主干，再清楚分叉到各子节点。
48. 具有共同子节点的多条关系可以在子节点附近汇入一段共同主干，但每个父来源必须仍然可辨。
49. 没有共同起点或共同终点的关系不得共享线段。
50. 线路不得出现没有避障必要的外围大绕行、回头线或重复折返。
51. 新增兄弟节点时，应保留原有兄弟的稳定顺序，并根据用户落点提示插入左侧、中间或右侧。
52. 没有明确插入提示时，使用以下稳定顺序：现有从左到右顺序优先，其次使用创建顺序作为确定性回退。
53. 刷新、重新打开、选择节点、平移、缩放、调整侧栏或移动无关内容不得改变合法层级的顺序和坐标。

---

# 7. 多父节点

54. 一个节点可以有多个父节点，但任意两个直接父节点之间不得存在直接或间接的祖先/后代关系。
55. 两个直接父节点可以彼此无关，也可以同属更上游节点的平级分支。
56. 新增父节点会使任意两个直接父节点互为上下游时，必须拒绝整个操作并给出明确原因。
57. 多父节点布局必须采用有向无环图的分层结果，不得把同一实体复制成多个视觉节点。
58. 多个直接父节点应尽量位于同一视觉层；如果各自上游深度不同而无法同层，也必须保持每个父节点位于共同子节点上方。
59. 共同子节点应尽量位于其父节点组合的视觉中心下方，父线路在共同子节点附近清楚汇合。
60. 新增第二个或更多父节点时，可以重新排列合并后的整个受影响连通层级，以避免产生局部正确、整体混乱的布局。
61. 多父关系布局仍不得移动无关自由节点或其他连通层级。

---

# 8. 批量关系

62. 多选节点拖到未选目标节点上时，继续遵守 1.3 第 82 条的原子合法性要求。
63. 批量关系成功后，不保留被选节点组的精确坐标，但必须保留它们在操作前已经形成的稳定左右顺序。
64. 如果操作前无法区分左右顺序，则按选择锚点顺序和创建顺序确定稳定结果，不得随机排列。
65. 批量关系中的所有关系和自动排列必须共同作为一次原子操作成功或失败。
66. 任一关系非法或最终无法生成合格布局时，不创建任何候选关系，所有节点恢复到操作前位置。

---

# 9. 解除关系

67. 工具栏“解除”仍删除所选节点的全部父级关系；双击关系独有线段仍只删除该关系。
68. 解除关系只改变结构，不自动改变幸存节点的当前坐标。
69. 某节点解除后失去全部父级时，成为当前坐标上的新根节点。
70. 解除后形成独立子树的，后续拖动其根节点按第 30 条整体移动。
71. 解除关系不得移动无关节点，也不得为了让图形更整齐而隐式运行整图布局。

---

# 10. 稳定性、性能与撤回

72. 自动布局只在建立、增加或批量建立关系的提交阶段运行，不因选择、悬停、平移、缩放或无关移动触发。
73. 布局和路由计算只处理受影响连通层级及必要的只读障碍信息，不重新计算全部画布内容。
74. 节点和 SVG 元素应继续复用，不能因一次关系操作重建全部画布 DOM。
75. 同一结构、同一稳定顺序和同一障碍条件必须得到确定性的排列结果。
76. 建立关系及其自动排列共同占用一步撤回记录；撤回时关系和全部受影响坐标一起恢复。
77. 普通手动移动占用一步撤回记录；系统为寻找最近合法位置进行的小幅调整属于同一步操作。
78. 自动排列失败时不得留下部分移动、临时关系、残余线路或额外撤回记录。
79. 布局算法不得在拖动过程中高频运行，也不得通过过度枚举候选位置造成 Firefox 持续高资源占用。

---

# 11. ChatGPT 项目之间移动对话

80. 每个画布继续绑定 ChatGPT `conversationId`，不绑定项目名称、项目 ID 或完整页面 URL。
81. 同一个 ChatGPT 对话在项目之间移动、移入项目或移出项目，只要 `conversationId` 不变，原画布、备忘录、颜色和视图状态必须自动继续使用。
82. 项目移动不得创建画布副本，也不得因为项目名称变化而重置画布。
83. 如果 ChatGPT 某种操作实际创建了新的 `conversationId`，插件不得仅凭标题或正文相似就猜测并迁移画布。
84. ChatGPT “在新聊天中分支”继续适用 1.3 第 404～417 条的可靠分支复制规则，不等同于项目移动。
85. 实机验收必须覆盖：项目 A → 项目 B → 移出项目，并核对三次打开时的 `conversationId` 与画布一致性。

# 12. 操作失败与提示

86. 建立关系前必须先检查自指、重复关系、循环关系及多父节点互为上下游等语义非法情况。
87. 语义非法时直接拒绝，不运行昂贵的完整布局搜索，并说明具体原因。
88. 语义合法但有限画布中无法形成合格层级图时，关系和布局整体失败，提示：

**“无法建立该层级：当前没有合理的无冲突布局。”**

89. 普通手动移动在释放点及附近均没有合法解时，取消移动并提示：

**“无法放置：当前位置附近没有无冲突空间。”**

90. 所有失败均必须恢复操作前完整状态，不能以“部分成功”代替明确失败。

94. 1.3 第 157、160～162 条只继续约束连续新建但尚未建立关系的自动排列组；一旦建立关系，适用本文件的层级自动排列规则。
95. 1.3 第 200～209 条仅继续用于释放到空白处的普通手动移动；关系意图改用本文件第 34～42、62～66 条。

98. 1.3 的其他硬性无冲突、数据安全、正文锚点、备忘录、性能、隐私和 Firefox 兼容规则继续有效。

# 14. 1.5 必测验收场景

99. 无关系节点拖到空白处后停在释放点或最近合法点，其他内容不动。
100. 节点解除父关系后再移动，按手动落点处理，不自动归队。
101. 独立子树根节点移动时整棵子树刚性平移，内部排列和线路不散开。
102. 已关联节点普通移动后只更新相关线路，不触发整层级自动重排。
103. 孤立节点拖到已有父节点上后，自动进入下一层并与已有兄弟整齐排列。
104. 给已有子节点增加合法第二父节点后，合并层级整体形成清楚的多父布局。
105. 两个拟议父节点互为祖先/后代时，整个操作被拒绝且原图不变。
106. 批量无父节点拖到共同父节点后，保持原左右顺序并一次自动排列。
107. 新增关系导致空间紧张时，允许扩大到整个受影响层级重排，但自由节点和其他层级完全不动。
108. 同一画布重复刷新、关闭重开及重复计算时，合法层级顺序和坐标保持稳定。
109. 移动无关节点、平移、缩放、选择和修改颜色时，已有层级不得重新排列。
110. 自动布局过程中 Firefox 不出现持续高 CPU、明显卡顿或“扩展拖慢 Firefox”警告。
111. 关系与自动排列只占一步撤回；撤回后结构和全部位置完整恢复。
112. 对话移入另一个 ChatGPT 项目并再移出时，只要 `conversationId` 不变，始终显示同一画布。

# 15. 冻结原则

113. 1.5 实现不得把几何自动排列扩展为内容分析或自动建立关系。
114. 不为了追求专业制图软件功能增加小地图、复杂布局面板、AI 整理或多套隐藏布局模式。
115. 如果实现中发现某条规则在真实使用中产生明显不合理结果，应先记录可复现场景并与用户确认，不在代码中静默改变产品语义。
116. 只有代码、自动测试、Firefox 实机验收和本文件逐条校对全部完成后，才能把本文件状态改为“正式已实现基线”。
