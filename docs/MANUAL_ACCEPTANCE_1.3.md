# ChatGPT NET 1.3 — Windows Firefox 人工验收清单

**目标环境：** Windows Firefox 152+，当前生产 ChatGPT。
先在无重要内容的测试 conversation 中验证。任何**静默数据丢失、节点永久重叠、关系线穿过无关节点、非法线交叉/重叠、保存冲突静默覆盖**都属于发布阻断问题。

## 0. 本轮用户实测问题：必须先全部通过

- [ ] 正常桌面宽度下开启 ChatGPT NET 后，ChatGPT **正文和输入框的右边界都在侧栏左边界之前**；不能只是把侧栏盖在正文上。
- [ ] 对照开启前后，ChatGPT 主内容确实重新利用左侧空余空间并向左重排；左侧 ChatGPT 导航/rail 仍可正常使用。
- [ ] 调整侧栏宽度时，正文和输入框同步重新排版；不能出现内部 fixed/`100vw` 壳仍伸到侧栏下面。
- [ ] 页面内不存在 `>>` 或 `<<`。Firefox 工具栏图标亮时显示并运行；再次点击后图标灰、侧栏彻底消失、ChatGPT 恢复完整宽度。
- [ ] 灰色状态再次点击图标后恢复当前 conversation 的画布和视图；同一标签页刷新保持灰色关闭，关闭标签页/Firefox 重启后不继承该临时关闭状态。
- [ ] 工具栏按钮文字为 `解除`，不是“解除层级”。
- [ ] 普通单击节点只出现一个真实节点框和选中轮廓，不出现第二个空白/半透明框；不拖动时节点坐标不改变。
- [ ] 单击后节点仍可直接拖动；删除后真实节点和任何 ghost/空白残影都完全消失。
- [ ] 从正文创建的节点，其节点实际颜色与对应正文高亮是同一颜色的实体/半透明表现；改色后两者同步对应。
- [ ] 工具栏固定只有 **3 个**颜色槽 + 1 个共用齿轮。
- [ ] 在画布空白处单击、拖动或滚轮时，ChatGPT 正文不得发生任何跟随滚动。
- [ ] 移动自由节点或另一连通分量时，既有无关关系线坐标和视觉元素保持不变，不出现全图跳线/闪烁。

## A. Firefox 工具栏生命周期与后台停止

- [ ] 加载临时扩展后，ChatGPT 标签页图标亮，且只出现一个 ChatGPT NET 侧栏。
- [ ] A 标签页点击图标变灰并关闭 NET，不影响 B 标签页的 NET 状态。
- [ ] 灰色状态下检查页面：无侧栏、无正文高亮、无创建节点 popup、无 NET ghost/遮罩。
- [ ] 关闭前正在拖节点、平移画布、调整节点宽度、调整侧栏或分隔线时点击 Firefox 图标：未完成手势取消并恢复，不留下卡死 pointer/ghost。
- [ ] 关闭前正在编辑节点/备忘录文字时点击 Firefox 图标：已输入内容按正常 blur/提交语义结算，不因 DOM 被移除而静默丢失。
- [ ] 关闭后等待 ChatGPT 流式生成/滚动数分钟，不应重新出现侧栏或高亮，也不应继续运行画布 sleep/message observer 等持续工作。
- [ ] 灰色状态同一标签页刷新后仍灰；点击后恢复。
- [ ] 关闭该标签页并新开 ChatGPT 标签页，或重启 Firefox 后打开/恢复标签页：默认亮色开启。

## B. 页面空间关系与尺寸

- [ ] 默认侧栏约 420 CSS px；画布内部初始设计宽度约 360 CSS px（空间允许时）。
- [ ] 侧栏拖到设计上限时，画布视口不超过 720×900 CSS px；世界边界不随侧栏变化。
- [ ] 新画布世界边界固定为 2880×3600；25% + 720×900 视口可看到完整边界。
- [ ] 新画布 75% 缩放，视图中心横向约世界 1/2、纵向约世界上 1/4。
- [ ] 画布/备忘录默认约 75%/25%，拖动分隔线后比例保存；调整比例/侧栏宽度不改变 zoom。
- [ ] 浏览器缩窄到确实无法给 ChatGPT 留足合理宽度时才进入 overlay；此时仍可通过 Firefox 工具栏图标直接关闭。
- [ ] 关闭 NET 后 ChatGPT 的 width/max-width/margin 等恢复到开启前，不残留布局污染。

## C. 正文摘录与连续摘录

- [ ] 在用户消息和助手消息正文中选择文本，普通模式只在选区附近出现“创建节点”。
- [ ] 点击“创建节点”后原生选区尽量仍保留，可以继续复制；同一段正文可重复创建不同节点。
- [ ] 输入框、导航、菜单、复制/反馈按钮、NET UI 不触发“创建节点”。
- [ ] 一次选区跨两条及以上消息：按消息边界拆成多个独立节点；不自动建关系；一次 Ctrl+Z 全部撤回。
- [ ] 连续摘录开启后按钮有持续可见 active 状态；普通正文划选立即创建，不再出现“创建节点”。
- [ ] 连续摘录开启：Ctrl+正文划选不创建；Shift+正文划选不创建；Alt 没有 NET 语义。
- [ ] 切换 conversation 或刷新后连续摘录自动关闭。

## D. 节点显示、选择、编辑与移动

- [ ] 自由节点为明显虚线/无正文样式，可编辑、移动、调宽、改色、建关系、转备忘录。
- [ ] 普通单击一个新节点：清除画布原选择，只单选该节点。
- [ ] 多选后普通单击其中一个已选节点且不拖动：最终只保留该节点；但从任一已选节点真正拖动时仍整体移动全部已选节点。
- [ ] Ctrl+单击未选节点追加；Ctrl+单击已选节点取消。
- [ ] Shift+单击有锚点节点跳正文；Shift+单击自由节点等同普通单选。
- [ ] 画布和备忘录任何时刻都不能同时存在选择；特别测试“备忘录已选 → Shift+点画布锚点”和反向路径。
- [ ] 双击节点进入文字编辑；编辑只改显示文字，不改 original excerpt/anchor。
- [ ] 节点左右边缘调宽与移动是不同手势；长文本高度自动增长，最终不得与其他节点/线冲突。
- [ ] Esc、pointercancel 或窗口失焦取消未完成 drag/resize/pan/box/split/sidebar-resize 并恢复开始状态。
- [ ] 普通拖动平滑，无持续闪烁；拖动到视口边缘能自动平移。

## E. 画布选择、平移、缩放

- [ ] Ctrl+空白拖动框选；框选不平移。
- [ ] 普通空白拖动平移；普通空白单击清除画布选择。
- [ ] 多选整体移动保持相对位置，结束后仍满足全部硬性几何规则。
- [ ] Ctrl+滚轮以鼠标位置为中心缩放，范围严格 25%–300%；不使用 Alt+滚轮。
- [ ] 当前 zoom 百分比显示正确。
- [ ] 双击 zoom 百分比恢复 75% 并把当前画布内容居中，不改节点坐标、关系、侧栏宽度或 memo 比例。

## F. 多父层级与硬性关系路由

- [ ] 单个根节点拖到另一个节点：落点为父、被拖节点为子，箭头父→子。
- [ ] 单个已有父节点的子节点再拖到第二父节点：两个父节点彼此无祖先/后代关系时增加第二父且不替换第一父；两个父节点已有直接或间接层级关系时明确提示不能创建。
- [ ] 两个节点已经共同指向同一子节点后，尝试再给这两个父节点建立直接或间接层级关系：整个操作被拒绝，现有关系与位置不变。
- [ ] 自指、重复、循环关系全部拒绝。
- [ ] 多选全部为根节点时，整体拖到另一个未选节点：全部成为该节点的平级子节点，一次 undo 撤销全部关系。
- [ ] 多选中任一节点已有父级时再拖到另一节点：不建任何关系，整组回到拖动前位置。
- [ ] 批量候选任一关系不能合法路由时：全部失败，不允许部分成功。
- [ ] 建立关系后，受影响的层级按组织结构图排列：父节点位于上方并相对直接子节点跨度居中；同层兄弟横向排列；下一层继续递归采用相同规则。
- [ ] 无解时提示 `无法放置：当前位置没有无冲突空间。`；建关系无解提示 `无法建立该层级：当前没有无冲突路径。`。
- [ ] 密集布局最终无节点边框重合；线不穿/碰无关节点；无共同端的线不交叉、不重叠。
- [ ] 只有共同父或共同子允许端点附近短共享主干，离开主干后关系可区分。
- [ ] 同层兄弟使用“父节点下边缘 → 共享竖向主干 → 同一条横向总线 → 各子节点竖向分支”的少折线结构；无障碍时不出现无意义绕远或重复折返。
- [ ] 结构排列只作用于本次关系或普通移动涉及的连通层级；普通移动先尝试用户落点和局部调整，仍不能得到清晰短线时可整理该连通层级，但无关自由节点、其他连通分量及其合法线路的位置不变。
- [ ] 无关自由节点占据层级首选位置时，相关层级作为整体换到附近合法位置；不得移动无关节点，也不得改用绕画布外圈的长线路强行建立关系。
- [ ] 多父节点及两层以上结构中，每条已接受关系仍只在父层与子层之间向下连接，路径最多四个点；无法生成这种结构线路时取消本次关系。
- [ ] 双击独有线段只删该关系；双击真实共享主干不删并提示 `无法删除`；邻近平行线不能被误判为共享主干。
- [ ] 选中多个节点点击 `解除`：只删除这些节点全部父级关系，保留它们指向下游的关系。

## G. 删除、折叠与自动排列

- [ ] 删除节点同时删与它直接相连的所有关系，不删除子节点；幸存子节点失去全部父级时自然成为根。
- [ ] 批量删除一次完成、只占一步 undo；未删除节点之间原关系保留。
- [ ] 折叠只允许隐藏的全部下游都没有多父；含多父时 hover 显示 `包含多父节点，无法折叠`。
- [ ] 合法折叠隐藏下游节点/线；展开完全恢复；折叠/展开不进入 history。
- [ ] 连续新建节点横向优先：第一个当前可视区中下部居中；第二/第三加入时整行重新居中；满行换下一行。
- [ ] 自动排列组内节点未被移动/用于建立层级前，后续新节点可继续重居中；文本编辑/改色不结束组。
- [ ] 手动移动或建立层级后旧自动组终止，后续新节点不得再移动旧组。
- [ ] 下方空间不足时可整体向上平移已有内容，但始终保持节点/线路合法。
- [ ] 彻底无合法空间时提示 `画布已满`，不在世界边界外偷偷创建。

## H. 备忘录与分隔标题

- [ ] 画布节点拖入备忘录：进入分隔线附近的扩大命中区或 memo 区即出现高层 ghost 和整区“释放到备忘录”反馈，ghost 不被 memo 遮挡；释放后才转换。
- [ ] 转入后保留显示文字、original excerpt、anchor、实际颜色；画布无隐藏副本，旧关系不保存。
- [ ] 单个 memo 条目拖回：成为独立根；释放点优先，冲突时找附近合法点；失败则留在 memo。
- [ ] 多选 memo 条目一起拖回：按当前视觉顺序、横向优先、整体邻近释放点、全成或全败；一次 undo。
- [ ] `备忘录` 标题行右侧 `＋` 创建内联分隔标题输入并自动聚焦，不弹中央 modal。
- [ ] 双击标题改名；拖标题时标题+内部条目整体排序。
- [ ] 未分组条目可进入/移出标题，也可位于不同标题之间。
- [ ] 删除标题只删除标题，内部条目按原顺序变成未分组。
- [ ] 标题折叠显示数量；搜索/定位可自动展开。
- [ ] 标题分组有明确的“分组”徽标、左侧色条和缩进容器；其中条目一眼可与未分组条目区分。
- [ ] Memo 普通/Ctrl/Shift 点击遵守统一选择语义；批量排序/入标题保持相对顺序并原子完成。
- [ ] 删除 memo 条目是真删除，不返回画布；单/批量都可 undo，批量一步。

## I. 三色系统与正文高亮

- [ ] 默认只有雾蓝、鼠尾草绿、浅沙黄三个槽；始终有一个 active 槽。
- [ ] 无选择时点颜色槽只切 active；有画布或 memo 选择时，同时批量改色且一步 undo。
- [ ] 新节点使用当前 active 槽实际颜色。
- [ ] 共用齿轮可用 color picker 和 RGB 修改 active 槽，并明确选择“当前对话”或“全局默认”。
- [ ] 改槽定义不改已有对象实际颜色；以后新建/重新改色才用新值。
- [ ] 无 conversation override 时随全局默认；建立 override 后三槽成为完整独立副本。
- [ ] active 槽按 conversation 保存；刷新、关闭后重新开启、离开再进入均恢复。
- [ ] 分支继承来源当时三个实际槽并成为独立副本；分支 active 固定从第 1 槽开始。
- [ ] 每个锚点节点/memo 条目的 ChatGPT 正文高亮使用该对象实际颜色的半透明表现；同一原文映射多个不同颜色对象时能同时表达颜色。
- [ ] 选中状态使用高对比 outline，不只靠填充色。

## J. 搜索与正文双向定位

- [ ] 搜索只限当前 conversation，匹配显示文字、original excerpt、自由节点、memo 条目和分隔标题；普通 substring，不解释正则。
- [ ] Ctrl+F 仍属于 Firefox/ChatGPT。
- [ ] 搜索结果定位不改 zoom、不全局重排；必要时只展开目标所在 memo 标题/可折叠层级。
- [ ] Shift+锚点对象定位到正文并临时强化对应高亮；自由节点只普通选择。
- [ ] 修改/重新生成消息后：精确 excerpt 找不到但整条消息可靠时只定位消息并提示；不可靠时标记无法定位且绝不跳错消息。
- [ ] 点击正文高亮反向定位 NET；同一 excerpt 对应多个对象时出现小型选择列表。
- [ ] 页面/侧栏尺寸变化导致 ChatGPT 重排后，高亮 rect 随正文重新计算，不停留在旧位置。

## K. Undo/Redo

- [ ] 连续执行至少 16 个结构操作：只能撤回最近 15 步；新动作发生后 redo 链清空。
- [ ] Ctrl+Z / Ctrl+Shift+Z 工作；NET 不使用 Alt。
- [ ] 跨消息一次摘录、批量删除、批量移动、批量共同父关系、批量改色、批量 memo 返回/排序/删除/入标题都各占一步。
- [ ] 节点/层级折叠、memo 标题折叠、pan、zoom、侧栏宽度、memo 比例、选择、搜索词、sleep/wake、颜色槽定义、仅切 active 槽、Firefox 图标关/开不进入 history。
- [ ] 结构编辑后再改变 pan/zoom/collapse/active 槽，然后 undo 结构编辑：这些非 history 状态保持当前值。

## L. 休眠

- [ ] 连续约 10 分钟没有有效 NET 操作出现明显休眠遮罩。
- [ ] 休眠期间高频消息 observer/高亮刷新等安全后台处理暂停；节点、关系、memo、pan、zoom、比例均不变。
- [ ] 点击遮罩恢复；sleep/wake 不进入 history。
- [ ] Firefox 图标关闭不是“休眠中间态”：它必须直接销毁侧栏 runtime；重新点图标才重新 mount。

## M. ChatGPT 分支

- [ ] 来源 conversation 中 NET 开启，现场点击 ChatGPT “Branch in new chat/在新聊天中分支”，同一标签页随后进入的新 conversation 才可能复制。
- [ ] 随便切到另一个新/旧 conversation、直接打开历史 branch，都不能误触发复制。
- [ ] 新 conversation 的消息历史必须与来源 fingerprint 可靠吻合；不能确认时宁可不复制。
- [ ] 自由节点复制；锚点节点只有在新 branch 中能**精确**重新定位才复制。
- [ ] 未复制节点相连关系丢弃，其余合法关系保留；多父结构仍合法。
- [ ] 新 branch 不继承 undo；来源与 branch 后续画布/三色槽完全独立。

## N. 导出、导入与数据安全

- [ ] 设置可导出当前和全部画布；导出前明确提示含 ChatGPT excerpt/anchor 信息。
- [ ] 备份含节点、original excerpt、anchor、位置、关系、memo、颜色、相关设置、branch origin；无需 history。
- [ ] 导入畸形 JSON、错误 product/baseline、循环关系、节点重叠、世界越界、非法 route、畸形 RGB、无效 anchor、非法 memo grouping：全部拒绝且现有数据不变。
- [ ] 与现有 conversation 冲突时明确选择“完整导入版本”或“完整现有版本”，不能 merge/静默覆盖。
- [ ] 备份中的全局默认设置另行明确选择导入/保留，不能和“保留现有画布”隐式混合。
- [ ] 1.3 不扫描/迁移 Chat Tree 0.4.3 或 `chat-tree:*` 数据。
- [ ] 保存失败提示可理解，不能静默丢内容。

## O. 隐私窗口、多标签页、恢复

- [ ] Firefox 扩展设置中允许隐私窗口后，private window 可正常使用；不出现首次“隐私摘录永久保存”提醒。
- [ ] 普通/private window 看到同一套本地 NET 数据；关闭 private window 不删画布。
- [ ] 刷新页面、关闭/重启 Firefox 后已保存画布恢复。
- [ ] 同 conversation 在两个标签页：A 保存后 B 的 stale 写入必须明确报 conflict，绝不能覆盖 A。
- [ ] conflict 或一般保存失败时错误提示在关闭侧栏等路径也不能被瞬间清掉而让用户无感知。

## P. ChatGPT 页面变化保护

- [ ] 助手流式生成、conversation rerender、页面组件频繁刷新时始终只有一个侧栏。
- [ ] 页面 rerender 不丢 canvas/memo 数据。
- [ ] 临时无法识别 message DOM 时保留全部已有内容和自由节点，暂停可能错误的新 anchor/定位；恢复识别后功能恢复。
- [ ] 不因 selector 失败把旧 excerpt 错绑到另一消息。

## Q. 500 节点性能门槛

- [ ] 约 500 节点及代表性关系规模下仍能实际使用。
- [ ] 正常节点拖动无持续明显卡顿/闪烁；空白 pan 和 Ctrl-wheel zoom 可用。
- [ ] 移动无关节点不触发既有合法线路的全量重新寻路或 SVG 全量替换；移动一个连通分量不改变其他分量的线路。
- [ ] 高密度路由不能通过放宽 hard geometry 来换性能；无合法解必须拒绝。
