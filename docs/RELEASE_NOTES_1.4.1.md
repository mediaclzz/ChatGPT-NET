# ChatGPT NET 1.4.1 发布说明

**发布日期：** 2026-08-09  
**功能基线：** ChatGPT NET Functional Baseline 1.4  
**数据格式：** schema 1；可导入 Baseline 1.3/1.4 备份

## 用户实测问题与根因

- Firefox 提示扩展拖慢浏览器：建立关系时旧代码把数百个候选位置与全图 A* 路由嵌套执行，最坏情况下单次操作可同步扩展为大量主线程搜索；每轮正文高亮又为每个锚点重复遍历消息 DOM。
- 连线和节点堆叠难读：旧逻辑优先保留鼠标释放位置，只尝试绕线和极小范围挪动，没有把新关系整理为可读的上游/下游结构；阻塞中的拖动预览还会停在父节点上方，形成截图中的重叠框。

## 修正

- 新增轻量有向分层布局器：最长路径分层、上下重心排序、兄弟分组连续、紧凑坐标分配。
- 建立关系后只重排相关连通分量；不移动无关自由节点或其他分量；普通手动移动仍保持自由布局。
- 常见层级优先生成父下边缘→子上边缘的短正交线，独立分配入/出端口；复杂自由布局才进入障碍路由。
- A* 与位置回退均设置固定预算，移除原先的多层穷举组合；无解快速回滚。
- 高亮刷新改成一次消息 DOM 索引、批量锚点定位；状态变化不再重绘整个画布。
- 新增 31 节点分层、树形路由、多父 DAG、无关节点不移动和布局性能测试。
- 浏览器集成新增关系耗时、短路径、父子层级、批量锚点 DOM 遍历次数以及 Chromium/Firefox 双引擎回归。

## 实测证据

- Chromium mock：单条建层级约 1.5 ms；50 次批量锚点定位约 0.2 ms。
- Firefox 141 mock：单条建层级约 2–3 ms；50 次批量锚点定位约 0–1 ms。
- 500 节点/100 关系 core route 约 19 ms；500 节点/360 关系 stress route 约 40 ms（本机本轮结果）。
- Firefox 视觉检查：父节点在上、子节点同层分列、关系为短正交线，无节点堆叠和绕远线路。

生产 ChatGPT 的实际消息数量、Firefox 日常 profile 中其他扩展以及用户已有画布密度可能影响绝对耗时，因此仍需按人工清单做一次生产页面复测；自动回归已覆盖本次两个可复现根因。
